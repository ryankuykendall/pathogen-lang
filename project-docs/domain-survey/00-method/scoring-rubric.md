# Scoring Rubric

Each domain is scored 1–5 on five axes; the **rubric score is the product**
(range 1–3125). The point is ranking, not precision — a product punishes any
axis at 1 and rewards balance.

| Axis | 1 | 3 | 5 |
|------|---|---|---|
| **Population** | <10k practitioners | ~100k–1M | 10M+ |
| **Pain intensity** | incumbents fine, mild annoyance | real recurring manual chore ("walking the pattern") | no viable tool; hand-drafting or $$$ CAD |
| **Pathogen fit today** | needs a different language | core model applies, missing pieces | could ship a demo this week with current features |
| **Inverse feature-gap cost** | needs multi-quarter engine work | 1–2 medium features | gaps are polish-level |
| **Early-adopter density** | GUI-only community, code-averse | tool-curious designer/seller subset | already code-native (writes scripts today) |

## Conventions

- **Population confidence tags**: every population figure carries `(H)`, `(M)`,
  or `(L)` confidence plus a source. Stage 1 figures are estimates marked
  *unverified*; Stage 3 verifies via web search and cites.
- **Community-signal proxies** (used when no survey/industry figure exists):
  subreddit subscribers, Discord/Facebook group sizes, Etsy listing counts for
  the domain's file type, flagship-hardware install base. Record the proxy used.
- **Tiers**: domains whose value depends almost entirely on `[G]` features
  (data import / HTTP) are tagged **Tier: data-driven** and ranked separately
  from **Tier: physical-output** domains where `cut()`/labels/offset is the
  differentiator.
