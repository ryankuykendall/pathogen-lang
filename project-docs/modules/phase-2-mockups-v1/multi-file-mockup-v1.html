Multi-file workspaces — mockup v1

1 · Files: a tree beside the editor recommended

  • Q1 (a). A Files pane is the first pane, and its toggle sits beside Console. The breadcrumb names the open file after the workspace.
  • Q2. Folders are paths with /, shown as a tree. This is the same shape as a CLI or VS Code project folder.
  • Q3 (b). The preview always shows main. Editing a library redraws main live, and a quiet label above the zoom controls says so. This changes decision 16 (main plus a pin), which 37- still records, so it needs your sign-off. Screen 6 shows the pin.
  • Q4. Main has a main badge and stays at the top of the tree. A program's row menu has Set as main. A new workspace starts as one main.pathogen. Libraries show a box icon and module;.
  • Q5. The + in the header offers New file and New folder. A row menu offers Rename…, Duplicate and Delete…. Rename takes a path, so it can also move a file.
  • Layout change: with the tree open the preview is about 500px wide. Today's top-center stale badge would run into the minimap and the fullscreen button there, so the badge and the label sit above the zoom controls (screen 4).
  • Not drawn: each file keeps its own undo history (Q8). The workspace saves as one unit, with one save status (Q9).
  • Open: Delete… needs a confirm step, which could name the files that import it. Rename could reuse the New file dialog instead of today's window.prompt. Only .pathogen files for now (Q10); each kind of file has its own icon, so data files can get theirs later.

2 · Files: tabs alternative · Q1 (b)

  • Open files are tabs above the editor. Main's tab has the main badge, and + opens New file.
  • Tabs hide two things: folders, and the files you haven't opened. Opening a closed file needs another way in, such as a file picker.
  • Not recommended for phase 2. A workspace holds a handful of files, and the playground has no tab strip yet (the audit lists it as missing).
State

3 · Files: tree and tabs alternative · Q1 (c)

  • The tree lists the whole workspace; the tabs hold the files you've opened.
  • This pays off with many files. With a handful, the tabs repeat the tree and take a row from the editor.
  • Recommendation: start with the tree (screen 1), and add tabs later if workspaces grow.
State

4 · Errors and navigation across files recommended · Q6, Q7

  • Q6. An error in another file names that file and its line, then each call that led there. This is how the CLI and VS Code print it. Every file and line in the panel is a link that opens that file at that line.
  • The tree puts an error dot on the file where the error happened and on main. Opening that file shows the squiggle at its line.
  • Each panel entry names its file, the open file included, so that every entry can be a link. Today's one-file panel reads Line 2:37 — ….
  • With the tree open, the error panel moves right to sit over the editor instead of the tree. Here it shows up to 7 lines; today's limit is 5. The stale badge moves down above the zoom controls (see screen 1).
  • Q7. Hovering an imported name says where it is defined, as in VS Code. Cmd-click (Ctrl-click) opens that file at the name.
  • Open: should the hover's "Defined in" be a link too? Console lines would name their file as well (not drawn here).
