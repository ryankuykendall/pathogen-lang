B · The Programs strip, compact recommended

  • Tighter than v2: frames 64×34 (v2: 104×62), names in 10.5px, 6px gaps, and no "Programs" header row. The tray is about 62px tall; v2's strip took about 115px.
  • It is a tray along the bottom of the preview, flush with the window's bottom edge, where the footer was. The zoom controls float just above it.
  • Same jobs as v2: click a frame to show that program large (the editor doesn't change). The shown frame is outlined; the primary has a small star.
  • The navigator: when you zoom in, the shown frame carries the view rectangle (state 3). At 64px it is small, but it still shows where you are, and you can drag it.
  • Editing a library (state 4): programs that import it get a dot; their frames dim and spin until they redraw.
  • Errors (states 5, 6): a red mark on the frame and the error dots in the tree; hovering says what went wrong. Shown large, the program is stale and the error panel sits over the editor, at the bottom edge now that the footer is gone. The stale badge is back at the top centre, where today's playground puts it.
  • No collapse button: at this height it isn't worth one. The tray is hidden when the workspace has one program.

F · A program chip at the top centre alternative

  • v2's "Showing main" label becomes a chip: a small picture of the shown program, its name, and a caret. Click it for a list of every program with a miniature: its name, its path, a star on the primary and a check on the one shown.
  • Click a row to show that program; the editor doesn't change. Hover a row for an "Open in the editor" button (state 2). This answers v2's question about double-clicking a miniature.
  • Editing a library (state 3): rows that import it get a dot, and their miniatures spin until they redraw. The chip stays on what's shown.
  • An error in another program (state 4): a red dot on the chip; its row says where it failed.
  • The stale badge moves under the chip, since the chip takes its spot.
  • No navigator. When you zoom in, the chip's small picture shows the view rectangle (state 5), but it is too small to drag. You pan by dragging the drawing, and Fit takes you back. This is the main thing F gives up against B.
  • Pros: takes no space; the list works for any number of programs; the shown program's name is always at the top.
  • Cons: the other drawings are one click away, and you only see that one broke from a red dot.
  • With one program, there is no chip.

G · The chip beside the zoom controls variation of F

  • The same chip and list as F, to the right of the zoom controls. The two are one group, centred at the bottom. The list opens upward.
  • The top of the preview is empty apart from the fullscreen button (left) and the inspector toggle (right). The stale badge stays at the top centre.
  • Pros: every view control in one place: zoom, then which program.
  • Cons: the shown program's name sits at the bottom, small, where it's easy to miss. The open list covers the lower half of the drawing. No navigator, as in F.

E · The primary: main.pathogen by convention from your v2 review

  • main.pathogen is the primary unless you choose another. A new workspace has only that file (screen 0, state 1). Thumbnails and publishing use the primary.
  • In the tree, the convention needs no mark: nothing is drawn on main.pathogen. When another program is primary, a small star follows its name (state 2), since the name no longer says it.
  • In the picker (strip or list), the primary always has its star and comes first.
  • Choosing: "Set as primary" in a program's row menu (state 1). On main.pathogen, while another program is primary, the same item puts it back.
  • Export (state 3): a fourth format, Project, downloads a .zip with every file and a pathogen.json whose main is the primary. The CLI and VS Code read that main: pathogen-lang my-gears compiles it. The workspace never lists pathogen.json; it is written on export. Importing a project folder reads main back.
  • Renaming the primary: it stays primary under its new name. Deleting it: main.pathogen takes over if there is one; if not, you're asked which program does.
  • Open: SVG, PNG and PDF export, and Snapshot, while another program is shown. Recommended: what you see is what you get, so they use the shown program and say its name ("Export try-sizes").

Recommendation

  • B, the compact strip. With the footer gone, it costs less height than the footer did, it shows every program at once, and it keeps a navigator.
  • F if you'd rather the preview have no tray. It is the better choice for workspaces with many programs. G puts the name where it's easy to miss.
  • Either way: no picker with one program; the primary first, with its star; "Show in preview" and "Set as primary" in the tree's row menu.
