# Dependency upgrade cycle — pathogen-lang (2026-09-05)

## Context

The root `package.json` has never been through a deliberate upgrade pass. `npm outdated` shows
32 outdated packages across the root, `api/`, and the two `packages/` manifests, including
several multi-major gaps (Vitest 1→5, TypeScript 5.9→7, ESLint 9→10, marked 15→18,
opentype.js 1.3→2.0, Puppeteer 24→25, Commander 14→15). Goal: assess each dependency
(upgrade or hold, with the reason), apply the upgrades in bisectable steps, and run the
relevant gate after each step so a regression is caught at the step that caused it.

regress); **include the packages/ step** (TypeScript 6.0.3 + LSP 10).

## Notes per risky step

**Vitest 1.6 → 4.1 predictions** (grepped: `vi.fn<` 0, `mockReset` 2, `restoreAllMocks` 0, `mock.results` 0, `toFake` 1, `getMockName` 0, 3rd-arg options objects 0, `vi.mock` 4 all with factories):

- `mockReset` (autosave tests) on bare `vi.fn()` → v3 "restore original" == undefined → same.
- Fake-timer `toFake` widening: `tests/compile-ticker.test.ts` pins its list; the two default users exercise only `setTimeout`/`Date.now` code. Fallback: pass an explicit `toFake` list.
- `tests/vitest.d.ts` `Assertion<T>` augmentation still valid in 4.x (`Matchers<R,T>` is a 5.x concern).
- `toMatchFileSnapshot` uses an absolute path → unaffected.
- `__dirname` in ~10 test files: still injected by Vitest 4; if `ReferenceError`, use the `fileURLToPath(import.meta.url)` pattern from `tests/svg-text-outliner.test.ts:11`.
- `jsTsFallback` plugin (`vitest.config.ts:8-21`): `resolveId`/`enforce:'pre'` unchanged in Vite 7; load-bearing for 12 tests importing `../playground/*.js`. If "Failed to load url …/playground/services/*.js" appears, strip the `?query` from `importer` before `dirname`.
- `coverage.all`/`basic` reporter: not used.

**TypeScript 6 config rationale:** `nodenext` (not `node18`) in `packages/*` because `pathogen-lang` is `"type": "module"` with `exports["."].types = ./dist/index.d.ts`; `node18` raises TS1479 for a CJS importer, `nodenext` allows `require(esm)` semantics and runtime resolves the `require` condition to `dist/index.cjs` anyway. `@types/node` is hoisted so `"types": ["node"]` resolves from `packages/*` via ancestor `typeRoots`; `vscode` types come from the explicit import.

**marked:** `marked-highlight@2.2.4` must land before/with `marked@18` (npm 11 peer resolution) — that's why it is in step 3. Blog index `pillWord` depends on the day (`build-blog.ts:638`) → run before/after captures the same day.
