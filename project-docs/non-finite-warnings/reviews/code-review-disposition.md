| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | **Critical** | A NaN in emitted path text corrupts the structured trace. The scanner that rebuilds commands from emitted text reads letters as commands, and `NaN` contains `a`, `Infinity` contains `t`. `circle(50, 50, sqrt(-1))` with `{ trace: true }` → **10 commands instead of 3**; `L calc(1/0) 20` → a phantom `t`. For raw arguments this was pre-existing and silent; for drawing functions it is newly reachable, because they used to throw | **Reproduced exactly** (`M a a a a a a a a a`; `M L a L`; `M L t L`) **and fixed at the root.** `src/evaluator/path-data.ts` is the single tokenizer module: `tokenizePathData`, `splitPathCommands`, and a new `hasCommandLetter()` (replacing the `/[MmLl…]/` regex heuristic in `evaluatePathCommand`) now read `NaN` / `Infinity` / `-Infinity` as NUMBERS before the command-letter rule or the number scanner runs — sign included, because left to the number scanner the `-` of `-Infinity` is a stray sign and is dropped. All four repro cases now trace as `M a a` / `M L L`. Tests: NaN, ±Infinity with sign, an arc beside its one-digit flag slots, packed `M0 0LNaN 5`, the display split, and that finite data tokenizes exactly as before. **Corpus:** 23,500 emitted path layers — none contains a non-finite word, and for every one the new command sequence equals the old letter-by-letter reading. |
| 2 | Critical (as filed) | Under strict mode, a warning raised inside `.map` / `.filter` / `.reduce` / `.sort` / `Grid.fill` / `Grid.forEach` / `Grid.map` gets a "double position prefix": `Line 3: Error in .map() callback at index 0: Line 4, col 5: … (strict: non-finite)` | **Declined — this is how every error inside a callback already reads.** Reproduced with no strict mode at all: an ordinary error → `Line 3: Error in .map() callback at index 0: Line 4, col 13: slice() start must be a number`; a failing `assert()` → the same shape. The outer part names the invocation, the inner part the position; a strict error follows the established format rather than introducing one. Pinned by a test so it stays deliberate. The reviewer was told and asked to say if it sees a reason strict should differ. |
| 3 | Warning | No cap or dedupe: `for (i in 0..2000) { M calc(1/0) 0 }` yields 2,001 identical warnings and log mirrors. `getDiagnostics()` dedupes editor-side; `result.warnings` and the CLI do not cap. The project was bitten by this shape before (thousands of marks at one site → stack overflow shown as a compile error) | **Declined as a source-side cap; verified end to end instead.** The published contract (`docs/debug.md` "Repeated warnings") is that `compile()`'s `warnings` and `--json` "keep every instance — nothing is collapsed there"; grouping is a display concern (`groupWarnings`, the CLI's `… N more like this`, `WARNING_GROUP_INSTANCE_LIMIT`). Capping at the source would break that. What mattered was whether the surfaces survive it: `verify/verify-playground.mjs` now loads a 2,000-iteration NaN loop — all 2,000 instances kept, the preview renders, no `Maximum call stack`, no page error. |
| 4 | Warning | Vacuous matrix in `tests/non-finite-warnings.test.ts`: 9 of the 10 context-aware functions throw with no arguments and hit `catch { return; }` before any `expect`; only `heading()` reached the assertion, trivially | **Agreed and fixed — in both files.** The same `catch { return }` shape was in `tests/path-emit-guard.test.ts`. Both loops now assert BOTH outcomes: a throw must be a positioned compile error that names the function (so a parse error in the template cannot satisfy it), and a non-throw must carry no non-finite token and no `non-finite` warning. A separate test proves the template compiles with a complete call. Still derived from `contextAwareFunctions`, not a per-function list. |

| 5 | Test quality | The linearity test in `tests/source-locations.test.ts` does not exercise the two-entry cache's reason to exist: its `calc()` bodies are under 512 characters and bypass the cache, so a regression to a one-entry cache would pass the whole file. Nothing pinned the cache-size choice | **Agreed and fixed — deterministically, not by timing.** The quadratic term a one-entry cache causes only dominates at sizes too slow for a unit test, so a timing test would be weak. `ast-builder.ts` now exposes an `@internal` cache-miss counter, and four tests pin the policy: two long sources alternating are each computed once; a third evicts the least recently used (pins "two, not more"); a short source between uses of a long one never evicts it; answers stay right across every eviction. **The tests were then proven to have teeth** by temporarily regressing the source: a one-entry cache fails the first; one entry with no bypass fails two; the file was restored byte-identical (`cmp`) and all 33 pass. |
