**Status: Proposed | Language: TypeScript | Namespace: Easing**

This document proposes a small, composable API for generating
interpolation functions that retain the ergonomic runtime shape of
lerp(start, end, time), while supporting normalized timing curves such
as sine and cubic Bézier easing as well as value-offset curves that can
oscillate or overshoot.

# 1. Goals

- Make every generated interpolator callable as (start, end, time) => value.
- Perform model-specific setup once, before the animation or hot path.
- Keep normalized timing curves and value-offset curves conceptually distinct.
- Support sine easing, mirrored/oscillating sine curves, and CSS-style cubic Bézier timing curves.
- Make future easing models easy to add without changing the runtime interpolation contract.
- Keep the implementation allocation-free during evaluation after a generator has been created.

# 2. Non-goals

- Arc-length parameterization for geometric Bézier paths.
- Vector, color, quaternion, or object interpolation in the first version.
- A physics-accurate spring solver.
- Implicit clamping of arbitrary output values. Overshoot may be intentional.

# 3. Core API Principle

The public namespace contains generators. A generator captures
configuration and returns a compiled Interpolator. Calling the resulting
function should feel no more complicated than calling lerp.

```ts
const smooth = Easing.sine({ mode: "in-out" });
const custom = Easing.cubicBezier(0.42, 0, 0.58, 1);
const wave = Easing.sineWave({
  amplitude: 20,
  halfCycles: 3,
});

const a = smooth(start, end, time);
const b = custom(start, end, time);
const c = wave(start, end, time);
```

# 4. Type Model

```ts
namespace Easing {
  export type TimingFunction = (time: number) => number;

  export type Interpolator = (
    start: number,
    end: number,
    time: number,
  ) => number;
}
```

TimingFunction is the normalized internal abstraction. It maps input
time to eased time. Interpolator is the public runtime abstraction and
maps a start/end range to a value.

# 5. Architecture

## 5.1 Shared interpolation adapter

Normalized timing models should not reimplement interpolation. They
produce a TimingFunction, which is adapted once through fromTiming().

```ts
namespace Easing {
  function lerp(start: number, end: number, time: number): number {
    return start + (end - start) * time;
  }

  function fromTiming(timing: TimingFunction): Interpolator {
    return (start, end, time) =>
      lerp(start, end, timing(time));
  }
}
```

## 5.2 Two curve categories

| Category     | Model                                  | Evaluation                          |
| ------------ | -------------------------------------- | ----------------------------------- |
| Timing remap | linear, sine in/out, cubic Bézier      | lerp(start, end, timing(t))         |
| Value offset | sineWave / oscillation                 | lerp(start, end, t) + offset(t)     |

This distinction is important. A cubic Bézier timing curve changes
progression through the start/end range. A sine wave with amplitude
modifies the value path itself and can intentionally overshoot the
range.

# 7. Sine Timing Generator

Easing.sine() represents conventional normalized sine timing. It always
begins at 0 and ends at 1 and is therefore appropriate for remapping
time.

```ts
export function sine(
  { mode = "in-out" }: SineOptions = {},
): Interpolator {
  switch (mode) {
    case "in":
      return fromTiming(
        t => 1 - Math.cos((Math.PI * t) / 2),
      );

    case "out":
      return fromTiming(
        t => Math.sin((Math.PI * t) / 2),
      );

    case "in-out":
      return fromTiming(
        t => (1 - Math.cos(Math.PI * t)) / 2,
      );
  }
}
```

# 8. Oscillating / Mirrored Sine Generator

Mirrored patterns such as rise-fall-rise are better modeled as an offset
from the ordinary interpolation baseline. This avoids inventing
progressively longer names such as easeInOutInOutSine.

```ts
export function sineWave({
  amplitude,
  halfCycles = 1,
}: SineWaveOptions): Interpolator {
  if (!Number.isFinite(amplitude)) {
    throw new RangeError("amplitude must be finite");
  }

  if (!Number.isInteger(halfCycles) || halfCycles < 1) {
    throw new RangeError("halfCycles must be a positive integer");
  }

  return (start, end, time) => {
    const base = lerp(start, end, time);

    const offset =
      amplitude *
      Math.sin(halfCycles * Math.PI * time);

    return base + offset;
  };
}
```

Amplitude is signed. A negative amplitude mirrors the value offset
vertically. halfCycles describes the number of alternating lobes and
scales without requiring new named easing variants.

```ts
const riseFallRise = Easing.sineWave({
  amplitude: 20,
  halfCycles: 3,
});

const inverted = Easing.sineWave({
  amplitude: -20,
  halfCycles: 3,
});
```

# 9. Cubic Bézier Generator

Easing.cubicBezier() follows CSS-style timing semantics. The four public
arguments are the two interior control points; the endpoints are fixed
at (0, 0) and (1, 1). Input time is an x-coordinate, not the Bézier
parameter itself.

```ts
const ease = Easing.cubicBezier(
  0.42, 0,
  0.58, 1,
);

const value = ease(start, end, time);
```

Evaluation therefore requires solving x(u) = time for the Bézier
parameter u, then evaluating y(u). Newton-Raphson provides a fast first
pass and bounded bisection provides a robust fallback/refinement.

```ts
function cubicBezierTiming(
  x1: number,
  y1: number,
  x2: number,
  y2: number,
): TimingFunction {
  const curve = (a1: number, a2: number, u: number) => {
    const c = 3 * a1;
    const b = 3 * (a2 - a1) - c;
    const a = 1 - c - b;
    return ((a * u + b) * u + c) * u;
  };

  const derivative = (
    a1: number,
    a2: number,
    u: number,
  ) => {
    const c = 3 * a1;
    const b = 3 * (a2 - a1) - c;
    const a = 1 - c - b;
    return (3 * a * u + 2 * b) * u + c;
  };

  const solve = (x: number) => {
    let u = x;

    for (let i = 0; i < 8; i++) {
      const error = curve(x1, x2, u) - x;
      const slope = derivative(x1, x2, u);

      if (Math.abs(slope) < 1e-7) break;
      u -= error / slope;
    }

    u = Math.max(0, Math.min(1, u));

    let low = 0;
    let high = 1;

    for (let i = 0; i < 12; i++) {
      const current = curve(x1, x2, u);

      if (Math.abs(current - x) < 1e-7) break;

      if (current < x) low = u;
      else high = u;

      u = (low + high) / 2;
    }

    return u;
  };

  return time => {
    if (time <= 0) return 0;
    if (time >= 1) return 1;

    return curve(y1, y2, solve(time));
  };
}

export function cubicBezier(
  x1: number,
  y1: number,
  x2: number,
  y2: number,
): Interpolator {
  return fromTiming(
    cubicBezierTiming(x1, y1, x2, y2),
  );
}
```

# 10. Cubic Bézier Validation

For a conventional timing function, x must be monotonic so each input
time has one unambiguous solution. Matching CSS constraints, x1 and x2
should be restricted to [0, 1]. y1 and y2 may be outside that range to
permit overshoot.

```ts
function assertBezierControlPoints(
  x1: number,
  y1: number,
  x2: number,
  y2: number,
): void {
  for (const value of [x1, y1, x2, y2]) {
    if (!Number.isFinite(value)) {
      throw new RangeError("control points must be finite");
    }
  }

  if (x1 < 0 || x1 > 1 || x2 < 0 || x2 > 1) {
    throw new RangeError(
      "cubic Bézier x control points must be in [0, 1]",
    );
  }
}
```

# 11. Time and Clamping Semantics

The low-level interpolator should have an explicit policy for time
outside [0, 1]. The recommended default is to clamp normalized timing
functions at their endpoints, because that matches typical animation
expectations. Value-offset models may either use the same policy or
expose an opt-in extrapolation mode in a later version.

- time <= 0 returns the start behavior.
- time >= 1 returns the end behavior.
- Cubic Bézier input time is clamped before inversion.
- Do not silently clamp y/output; Bézier or wave overshoot may be intentional.

# 12. Naming and Ergonomics

Keep the first three runtime arguments identical across all generated
functions: start, end, time. Configuration such as amplitude belongs in
the generator whenever it is expected to remain constant over an
animation.

```ts
// Preferred
const wave = Easing.sineWave({
  amplitude: 25,
  halfCycles: 3,
});

wave(start, end, time);

// Avoid as the primary API:
wave(start, end, amplitude, time);
```

This preserves the muscle memory of lerp(start, end, time) and makes
interpolators interchangeable.

# 13. Reference Implementation Skeleton

```ts
export namespace Easing {
  export type TimingFunction = (time: number) => number;

  export type Interpolator = (
    start: number,
    end: number,
    time: number,
  ) => number;

  export type SineMode = "in" | "out" | "in-out";

  export interface SineOptions {
    mode?: SineMode;
  }

  export interface SineWaveOptions {
    amplitude: number;
    halfCycles?: number;
  }

  function lerp(start: number, end: number, t: number): number {
    return start + (end - start) * t;
  }

  function clamp01(t: number): number {
    return Math.max(0, Math.min(1, t));
  }

  function fromTiming(timing: TimingFunction): Interpolator {
    return (start, end, time) =>
      lerp(start, end, timing(clamp01(time)));
  }

  export function linear(): Interpolator {
    return fromTiming(t => t);
  }

  export function sine(
    { mode = "in-out" }: SineOptions = {},
  ): Interpolator {
    switch (mode) {
      case "in":
        return fromTiming(
          t => 1 - Math.cos((Math.PI * t) / 2),
        );
      case "out":
        return fromTiming(
          t => Math.sin((Math.PI * t) / 2),
        );
      case "in-out":
        return fromTiming(
          t => (1 - Math.cos(Math.PI * t)) / 2,
        );
    }
  }

  export function sineWave({
    amplitude,
    halfCycles = 1,
  }: SineWaveOptions): Interpolator {
    return (start, end, rawTime) => {
      const time = clamp01(rawTime);
      return (
        lerp(start, end, time) +
        amplitude *
          Math.sin(halfCycles * Math.PI * time)
      );
    };
  }

  export function cubicBezier(
    x1: number,
    y1: number,
    x2: number,
    y2: number,
  ): Interpolator {
    assertBezierControlPoints(x1, y1, x2, y2);
    return fromTiming(
      cubicBezierTiming(x1, y1, x2, y2),
    );
  }

  // cubicBezierTiming() and validation omitted here
  // for brevity; see Sections 9 and 10.
}
```

# 14. Testing Strategy

## 14.1 Contract tests

- Every generator returns a callable Interpolator.
- linear()(a, b, 0) === a and linear()(a, b, 1) === b.
- Normalized timing easings preserve start and end values.
- Configuration is captured by the generator and does not mutate between calls.

## 14.2 Sine tests

- Sine in/out/in-out match known values at t = 0, 0.5, and 1.
- sineWave with amplitude 0 is equivalent to linear interpolation.
- Changing amplitude sign mirrors the offset around the linear baseline.
- halfCycles = 2 returns to the baseline at the end; halfCycles = 3 ends at a peak before endpoint clamping semantics are considered.

## 14.3 Cubic Bézier tests

- cubicBezier(0, 0, 1, 1) behaves approximately linearly.
- Endpoints evaluate exactly to start and end.
- x control points outside [0, 1] are rejected.
- y control points outside [0, 1] are accepted.
- Solver converges for flat and steep legal control-point configurations.
- Known CSS easing presets match reference values within a documented tolerance.

# 15. Performance

Generators may perform validation and precompute coefficients once. The
returned interpolator should avoid allocations. Cubic Bézier inversion
is the most expensive path; if profiling demonstrates a need, a small
x-to-u sample table can be precomputed by the generator and used to seed
or replace some solver iterations.

# 16. Extensibility

New normalized timing models should implement TimingFunction and reuse
fromTiming(). Models that alter the value path directly should implement
Interpolator. This permits future additions without weakening the public
contract.

```ts
Easing.quad({ mode: "in-out" });
Easing.expo({ mode: "out" });
Easing.cubicBezier(...);
Easing.spring({ damping: 0.7, frequency: 4 });
Easing.sineWave({ amplitude: 20, halfCycles: 3 });
```

# 17. Recommended Initial API

The first release should keep the surface deliberately small:

```ts
Easing.linear()

Easing.sine({
  mode: "in" | "out" | "in-out",
})

Easing.sineWave({
  amplitude: number,
  halfCycles?: number,
})

Easing.cubicBezier(
  x1: number,
  y1: number,
  x2: number,
  y2: number,
)
```

All generators return Easing.Interpolator, whose runtime call remains
(start, end, time). This provides a simple mental model, makes
configured easings interchangeable, and leaves room for both
conventional timing functions and intentionally non-monotonic
interpolation models.
