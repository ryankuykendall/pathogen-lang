- **2026-09-02, later**: Phase 2 shipped — the switch expression (`let x = switch (…) { case p { expr } default { expr } };`). Same clauses as the statement, one expression per arm, `default` mandatory in the grammar (which is what keeps it conflict-free against the statement: the generator reported none). Works on the right of `let`, in call arguments, in template interpolation, and inside `calc()` (the path-args tokenizer now nests braces inside parens). Not inside a style value's `${ }` (one brace level only) or as a bare path argument. Demo: `demo-expression.pathogen` + `.svg`/`.png`.
- **2026-09-06, syntax polish** (user request while writing `let offset = switch(normal.angle) { case 0..<1.25pi { randomRange(…); } … };`): (1) the canonical spelling is now `switch(value)` with the parenthesis against the keyword, like a call — formatter (both forms), completion snippet, VS Code snippet, hover, `docs/syntax.md`, the blog post and its post50 samples all print it; the parser still accepts `switch (value)`. (2) Expression arms accept an optional `;` after their expression (`case 1 { 4; }`). Grammar: `(";" ~armEnd)?` in `CaseArm`/`DefaultArm` plus a matching `~armEnd` after `ExpressionStatement`'s `;` — without the markers the generator reports the predicted shift/reduce between `DefaultArm → … expression ";" · "}"` and `ExpressionStatement → expression ";"` inside a `Block`. In statement position both readings now survive to the end of the switch, so `SwitchStatement` gained an optional trailing `";"` and `@dynamicPrecedence=1`: `switch(x) { case 1 { f(); } default { g(); } };` is the statement (before this it was a "Missing ';'" parse error, and with the arms change alone it became the expression reading and tripped "log() has no value"). The unreachable "A switch expression arm holds a single expression" diagnostic was removed; two expressions in an arm still error ("one expression per arm (a trailing ';' is fine)"). Code review then caught three shadow implementations of the same boundary that the grammar change did not reach: `src/parser/path-args-tokenizer.ts` ended the path-argument token at any `;`, so `L calc(switch(k) { case 1 { 5; } … })` broke — it now consumes `;` inside braces it opened, and a statement-only keyword (`let`, `for`, …) on a new line still ends the token so an unclosed arm brace reports next to the mistake; `TextSwitchStatement` gained the same optional trailing `;`; and the legacy `snippetTemplates` in `playground/utils/codemirror-setup.ts` still spelled `switch (`. Also fixed while there: a `calc()` whose content fails to parse used to fall back to an Identifier and surface as `Undefined variable: switch(k) { … }` at 1:1 — it now throws `cannot parse the expression inside calc()` at the offending token (`findExpressionErrorOffset` in lezer-expression.ts, injected via `setExpressionParser`). Verified CLI (tsx), playground (scratch workspace, error panel empty, negative control shows the new message), and the bundled LSP (formats to `switch(`, drops the arm `;`). Tests: parser (AST identical with/without `;`, statement precedence, two-expression rejection), evaluator, formatter normalization, diagnostics, completion snippet.
