# Gradient Blogpost Roadmap

## Objective

Produce a multiple blog posts (3-4) covering all of the work that we have done on adding gradients to Pathogen.

## Prerequisite phases

1. PHASE 1: We need the ability to pre-compile code-samples into SVGs from the command-line. Because some of our new gradients rely on WebGPU, we need to extend the compiler such that it can utilize a headless browser (likely Puppeteer) to optimally render Pathogen SVGs that employ Conic, Mesh, Freeform, and Topo gradients
2. PHASE 2: In the blog post, we want to be able to show the code and the rendered SVG output side-by-side. The ideal format would be an SEO optimized web component that upgraded with limited playground workspace functionality (Read-only CodeMirror, Copy Button for the code sample, Zoomable / Pannable preview panel with image navigator in top left, Open in new workspace button that navigates the user to the New workspace creation page in the Playground.) We would call this a mini-workspace. The expectation with the web-component is that it is for display purposes only. The component _would not_ compile the Pathogen code. It simply render the code in Code Mirror with syntax highlighting and allow the user a preview and navigate a pre-compiled SVG. Ideally we would create a build pipeline (code => compiled svg => HTML document fragment as a standalone file that could be put in version control; would likely put the code + compiled SVG in version control as well.)
3. PHASE 3: Because we are doing the work to develop a pipeline for either the compiler or a script to generate a Pathogen SVG in Puppeteer, we will want to be able to generate a bare bones web page (BBWP) that loads the compiler, compiles Pathogen code somewhere on the page (ideally just in a HTML <code /> tag) and outputs the SVG. We want something super barebones so that it can be served with a simple Node based webserver (not wrangler) and trivial for Claude Code to request an SVG and potentially a screenshot of the fully rendered SVG from Puppeteer.

NOTE: We may want to have two classes of BBWPs: Dynamic (which loads the compiler, compiles the Pathogen code in the browser, and renders the SVG) and a Static version (just the code + previously rendered SVG file? Need to discuss / think this through) 4. Phase 4: Add GroupLayer(layerName: string) as a new layer type (based on Native SVG's <g> tag) to Pathogen so that users can more easily organize and layout their PathLayers and TextLayers. GroupLayers would be limited to StyleBlockAttributes translate, scale, rotate. 5. Phase 5: Generate all code samples with labeling and schematics that will be used in the blog posts, and review them and their output in a collection of our static bare bones web pages (BBWPs.) 6. Phase 6: Author and publish the blog posts using generated the generated Pathogen Code samples and SVGs.
