# Website

Cloudflare Pages deployment — static assets, SPA routing, and API endpoints.

## Directory Layout

```
website/
├── _worker.js        Cloudflare Pages worker (SPA routing, API, SEO pages)
├── index.html        SPA entry point (redirects to /pathogen/)
├── blog/             Blog post HTML (generated by scripts/build-blog.ts)
├── blog-static/      Blog static assets (images, etc.)
├── docs-static/      Documentation static assets
└── bbwp/             BBWP render artifacts (see below)
```

## BBWP Archive (`website/bbwp/`)

The `bbwp/` directory is the canonical location for generated Bare-Bones Web Page render artifacts. These are self-contained HTML files wrapping compiled SVG output from `.pathogen` source files — used to preview, verify, and archive rendering results in a browser.

The compilation script auto-detects whether the source uses GPU gradient types (ConicGradient, MeshGradient, FreeformGradient, TopoGradient) and chooses the appropriate rendering path:
- **GPU path**: Headless Chrome via Puppeteer (WebGPU/Canvas 2D pipeline)
- **CPU path**: String-based SVG generator (no Puppeteer, much faster)

### Compiling a BBWP

Use the `/bbwp` Claude skill or run the script directly:

```bash
npm run compile:bbwp -- <pathogen-file> [options]
```

The script auto-detects viewBox/width/height from source comments, derives roadmap/feature names from the file path, renders the SVG, wraps it in HTML, saves to `website/bbwp/`, and updates the index.

### File Naming Convention

```
YYYY-MM-DD-HH:MM:SS--${roadmapName}--${briefNameOfFeatureBeingTested}.html
```

Examples:
```
2026-03-05-14:30:00--gradient-blogpost--conic-inner-radius.html
2026-03-05-15:45:12--gradient-blogpost--mesh-bilinear-comparison.html
2026-03-06-09:00:00--phase-3--topo-laplace-10-panel.html
```

- **Timestamp**: ISO-ish local time when the artifact was created
- **Roadmap name**: The roadmap or feature initiative this artifact belongs to (kebab-case). Auto-derived from `project-docs/<roadmap>/` path structure; defaults to "misc".
- **Feature name**: Brief description of what's being tested/demonstrated (kebab-case). Auto-derived from the filename.

### Rules

1. **Never overwrite** an existing BBWP file. Always create a new file with a new timestamp so we preserve the full history of iterations and attempts.
2. **Version control is optional** — the user decides whether to commit BBWP files. They serve as a paper trail of rendering verification work.
3. **Update the index** after adding a new file by running:
   ```bash
   npm run update:bbwp-index
   ```
   This regenerates `website/bbwp/index.html` with links to all BBWP files in descending order (newest first). The script scans the directory and replaces the content between `<!-- BBWP_INDEX_START -->` and `<!-- BBWP_INDEX_END -->` markers. The `compile:bbwp` script does this automatically.

### Viewing BBWP Files

- **Local**: `npm run serve:bbwp` → open `http://localhost:3001/website/bbwp/`
- **Individual files**: open any `.html` file directly in a browser (they are self-contained)

## Deployment

The `website/` directory is not deployed directly. The `scripts/build-website.ts` script assembles the full Cloudflare Pages output in `public/` by copying playground, docs, blog, and static assets. The `_worker.js` file handles SPA routing and API endpoints at the edge.

```bash
npm run build:website    # Full build → public/
npm run dev:website      # Build + serve via Wrangler at localhost:3000
```
